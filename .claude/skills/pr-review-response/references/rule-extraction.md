# ルール化判断基準

PR レビュー対応で得た知見をルールとして採用するかの判断基準と、追加先の決定方法。

---

## ルール化の判断基準

### 採用すべきケース

| 条件 | 説明 |
|------|------|
| **再発防止が必要** | 同じ指摘が繰り返し発生する可能性が高い |
| **コンテキスト非依存** | 特定の機能や実装に限定されず、汎用的に適用できる |
| **明確な基準** | 判断に曖昧さがなく、機械的に適用可能 |
| **チーム合意** | ユーザー（チーム）が採用を承認している |

### 採用しないケース

| 条件 | 説明 |
|------|------|
| **一回限りの指摘** | この特定ケースでのみ発生した問題 |
| **好みの問題** | 正解がなく、プロジェクトやチームの好みに依存 |
| **既にルール化済み** | 既存のルールでカバーされている |
| **実装済みの仕様** | コードとして既に強制されている（enum定義など） |

---

## 抽象化のプロセス

レビューコメントからルールを抽出する際は、以下のステップで抽象化する。

### Step 1: 具体的な指摘を特定

```
元のコメント:
「create_trial アクションで from_raw() を使わないでください。
 mutation メソッドを使って状態を変更してください。」
```

### Step 2: 「なぜ」を問う

- なぜ `from_raw()` を使ってはいけないのか？
  → `from_raw()` は DB からの再構築用であり、Action 層の責務ではない
- なぜ mutation メソッドを使うのか？
  → カプセル化を維持し、`updated_at` の自動更新を保証するため

### Step 3: コンテキストを除去

```
抽象化前: 「create_trial アクションで from_raw() を使わない」
抽象化後: 「Action 層で from_raw() を使用しない（リポジトリ層専用）」
```

### Step 4: 適用範囲を明確化

```
適用範囲: backend/src/domain/actions/**/*.rs
例外: なし
```

## 追加先の決定

### 既存ルールファイルの確認

`.claude/rules/` 配下の関連ファイルを読み込み、以下を確認:

1. **重複確認** - 既に同等のルールが存在しないか
2. **矛盾確認** - 新ルールが既存ルールと矛盾しないか
3. **配置場所** - どのセクションに追加するのが適切か

### 追加先の選択

| ルールの種類 | 追加先 |
|-------------|--------|
| ドメイン層の設計ルール | `.claude/rules/backend/domain.md` |
| リポジトリ層のルール | `.claude/rules/backend/repository.md` |
| ユースケース層のルール | `.claude/rules/backend/use-case.md` |
| テストのルール | `.claude/rules/backend/testing.md` |
| 横断的なルール | `.claude/rules/backend/layer-checklist.md` |
| 新規カテゴリ | 新しいルールファイルを作成 |

### 矛盾の解消

既存ルールと矛盾する場合:

1. **既存ルールが古い** → 既存ルールを更新
2. **両方正しいが文脈が違う** → 条件を明確化して両立
3. **判断が難しい** → ユーザーに確認

**例: 矛盾の解消**

```markdown
## 以前のルール
「モデルのメソッド: ファクトリ（new()）とゲッターのみ」

## 新しい知見
「mutation メソッド（set_xxx）で状態変更を行う」

## 解消後
「モデルのメソッド:
- ファクトリ: new() - 新規作成時に使用
- ゲッター: フィールドへのアクセス
- ミューテーションメソッド: set_xxx(), add_xxx() など - 状態変更を担当」
```

## ルールの記述形式

### 必須要素

```markdown
**{ルール名}**: {1行での説明}

{より詳細な説明（必要に応じて）}

```rust
// ✅ 正しい例
{コード例}

// ❌ 間違った例
{コード例}
```
```

### チェックリストへの追加

ルールファイルにチェックリストセクションがある場合は、対応する項目を追加する。

```markdown
## チェックリスト

- [ ] {既存項目1}
- [ ] {既存項目2}
- [ ] {新規ルール項目} ← 追加
```

---

## コミットメッセージ

ルール追加時のコミットメッセージ形式:

```
docs: add {rule summary} to {file}

{詳細な説明}
- {ルール1}
- {ルール2}
...
```

**例:**
```
docs: add domain layer rules for mutation methods and from_raw usage

Add coding rules extracted from PR review:
- Mutation methods for state changes (set_xxx, add_xxx, remove_xxx)
- from_raw() restricted to repository layer only
- Parent-child construction order (parent → child → grandchild)
```
